# Awesome-Picture-Archiving-n-Communication-System

## Top PACS (Picture Archiving & Communication System) Ecosystem

**Curated List of SaaS Products & Open-Source GitHub Projects**
*Focused on Medical Image Archiving, DICOM, Radiology Workflow, Enterprise Imaging, VNA & Clinical Image Viewing*
**Last updated: September 2026**

This repository tracks notable **SaaS/hosted platforms**, commercial enterprise products, and **open-source projects** for **Picture Archiving and Communication Systems (PACS)**.

PACS platforms store, retrieve, distribute, visualize, and manage medical images and related data generated by modalities such as **CT, MRI, X-ray, ultrasound, mammography, PET/CT, nuclear medicine, pathology, ophthalmology, and other clinical imaging systems**. Modern PACS ecosystems increasingly integrate with **RIS, HIS, EHR/EMR, VNA, DICOMweb, AI applications, workflow engines, patient portals, and enterprise imaging systems**.

**Examples** include Intelerad, Visage Imaging, Philips IntelliSpace, Merge PACS, RamSoft, Novarad, FUJIFILM Synapse, Carestream Vue PACS, Agfa Enterprise Imaging, and INFINITT PACS (the category leaders).

**Open-source emphasis**: The open-source medical imaging ecosystem is particularly strong. While commercial PACS platforms provide integrated enterprise workflows and vendor support, open-source projects provide mature building blocks for **DICOM archiving, image routing, web viewing, desktop diagnostics, DICOMweb APIs, research imaging, AI integration, VNA-style storage, and interoperability**. Major projects include Orthanc, dcm4chee, Dicoogle, OHIF, Horos, Weasis, DCMTK, GDCM, CornerstoneJS, and many others. Open-source PACS deployments are commonly assembled from multiple interoperable components rather than a single monolithic application.

Contributions welcome! Open a PR to add or update entries. Keep descriptions factual and link to official sites or GitHub repositories.

## Open-Source GitHub Projects

* **[Orthanc](https://github.com/orthanc-server/orthanc)**
  One of the most important open-source DICOM servers and lightweight PACS platforms. Orthanc provides DICOM storage, querying, retrieval, REST APIs, DICOMweb capabilities through plugins, and extensive integration possibilities. It is commonly used as the core archive for self-hosted imaging platforms.

* **[DCM4CHEE Archive](https://github.com/dcm4che/dcm4chee-arc-light)**
  Mature open-source enterprise DICOM archive and image-management platform built on the dcm4che ecosystem. Supports DICOM storage, retrieval, DICOMweb, workflows, integrations, and scalable enterprise deployments.

* **[dcm4che](https://github.com/dcm4che/dcm4che)**
  Major open-source Java toolkit for DICOM and healthcare imaging applications. Provides libraries and applications for DICOM networking, data manipulation, image management, and enterprise imaging integrations.

* **[OHIF Viewer](https://github.com/OHIF/Viewers)**
  Leading open-source zero-footprint web-based medical imaging viewer. Supports configurable DICOMweb data sources, 2D and 3D visualization, MPR, annotations, segmentation, structured reports, microscopy, and extensible imaging workflows.

* **[Dicoogle](https://github.com/bioinformatics-ua/dicoogle)**
  Open-source PACS archive and medical-image indexing platform designed around flexible metadata extraction, indexing, search, storage, and retrieval, including support for private DICOM attributes.

* **[Weasis](https://github.com/nroduit/Weasis)**
  Powerful open-source DICOM viewer for desktop and web-integrated use. Supports PACS and DICOMweb integration, advanced visualization, MPR, 3D imaging, annotations, quantitative imaging, and AI-assisted workflows.

* **[Horos](https://github.com/horosproject/horos)**
  Open-source medical-image viewer for macOS derived from the OsiriX open-source ecosystem. Supports DICOM image viewing, advanced visualization, plugins, and research or clinical imaging workflows.

* **[CornerstoneJS](https://github.com/cornerstonejs/cornerstone3D)**
  Open-source JavaScript framework for building browser-based medical imaging viewers. Provides rendering, visualization, annotation, segmentation, and extensible DICOM imaging components.

* **[Cornerstone Legacy](https://github.com/cornerstonejs/cornerstone)**
  Widely used open-source web medical-imaging library that provides browser-based DICOM image rendering and visualization components.

* **[DCMTK](https://github.com/DCMTK/dcmtk)**
  Mature open-source collection of libraries and command-line tools for implementing DICOM applications. Widely used for DICOM networking, image conversion, querying, storage, and interoperability.

* **[GDCM](https://github.com/malaterre/GDCM)**
  Grassroots DICOM is an open-source cross-platform library for reading, writing, converting, anonymizing, and processing DICOM medical-image data.

* **[DICOMweb Server](https://github.com/GoogleCloudPlatform/healthcare-data-harmonization)**
  Open-source and cloud-native healthcare tooling can be combined with DICOMweb implementations for interoperable medical-image APIs and cloud imaging architectures.

* **[DICOMcloud](https://github.com/DICOMcloud/DICOMcloud)**
  Open-source DICOMweb-oriented medical imaging server designed around web APIs for DICOM image storage, retrieval, and cloud-based imaging workflows. OHIF documentation lists it among commonly used open-source DICOM image archive options.

* **[Conquest DICOM Server](https://github.com/marcelvanherk/Conquest-DICOM-Server)**
  Lightweight open-source DICOM server and PACS solution supporting DICOM networking, image storage, querying, routing, and integration with imaging systems.

* **[Kheops](https://github.com/kheops-online)**
  Open-source ecosystem for medical-image sharing, DICOM data management, research imaging workflows, and web-based collaborative access.

* **[PixelMed](https://www.pixelmed.com/)**
  Open-source Java DICOM toolkit and imaging library supporting DICOM networking, image processing, anonymization, conversion, and healthcare imaging applications.

* **[3D Slicer](https://github.com/Slicer/Slicer)**
  Major open-source medical-image computing platform supporting visualization, segmentation, registration, quantitative imaging, AI workflows, and DICOM integration.

* **[ITK](https://github.com/InsightSoftwareConsortium/ITK)**
  Insight Toolkit is a major open-source framework for medical-image processing, segmentation, registration, and analysis.

* **[VTK](https://github.com/Kitware/VTK)**
  Open-source visualization toolkit widely used for 2D and 3D scientific and medical-image visualization.

* **[MITK](https://github.com/MITK/MITK)**
  Medical Imaging Interaction Toolkit providing open-source tools and frameworks for medical-image processing, visualization, and application development.

* **[XNAT](https://github.com/NrgXnat/xnat)**
  Open-source imaging informatics platform for managing, sharing, analyzing, and organizing medical imaging and research data.

* **[XNAT-OHIF Viewer Integration](https://github.com/OHIF/Viewers)**
  OHIF-based viewing workflows can be integrated with research imaging platforms and DICOMweb archives to build browser-based imaging portals.

* **[OHDSI](https://github.com/OHDSI)**
  Open-source health-data ecosystem that can complement imaging platforms by connecting clinical data, analytics, observational research, and interoperable healthcare workflows.

* **[MONAI](https://github.com/Project-MONAI/MONAI)**
  Major open-source AI framework focused on healthcare and medical imaging. Useful for integrating AI inference and image analysis into PACS and enterprise imaging workflows.

* **[MONAI Deploy](https://github.com/Project-MONAI/monai-deploy-app-sdk)**
  Open-source framework for deploying medical imaging AI applications and integrating AI workflows with clinical imaging infrastructure.

* **[nnU-Net](https://github.com/MIC-DKFZ/nnUNet)**
  Highly influential open-source deep-learning framework for biomedical image segmentation, useful for PACS-connected AI and research imaging pipelines.

* **[NiftyNet](https://github.com/NifTK/NiftyNet)**
  Open-source deep-learning platform for medical-image analysis and imaging research.

* **[TotalSegmentator](https://github.com/wasserth/TotalSegmentator)**
  Open-source medical-image segmentation framework supporting automated anatomical segmentation for CT and other imaging workflows.

* **[pydicom](https://github.com/pydicom/pydicom)**
  Leading open-source Python library for reading, modifying, writing, anonymizing, and processing DICOM files.

* **[highdicom](https://github.com/ImagingDataCommons/highdicom)**
  Open-source Python library for creating and manipulating high-level DICOM objects including segmentations, structured reports, and quantitative imaging data.

* **[pynetdicom](https://github.com/pydicom/pynetdicom)**
  Open-source Python library implementing DICOM networking functionality for building Storage SCPs, Query/Retrieve services, modality integrations, and custom DICOM applications.

* **[SimpleITK](https://github.com/SimpleITK/SimpleITK)**
  Simplified open-source interface to ITK for medical-image processing and analysis in Python and other languages.

* **[NiBabel](https://github.com/nipy/nibabel)**
  Open-source Python library for accessing and processing neuroimaging and biomedical image formats.

* **[OpenSlide](https://github.com/openslide/openslide)**
  Open-source library for reading whole-slide digital pathology images, useful for pathology imaging archives and enterprise imaging platforms.

* **[Orthanc Explorer](https://github.com/orthanc-server/orthanc-explorer-2)**
  Open-source web interface and ecosystem components for interacting with Orthanc DICOM servers and building browser-based imaging workflows.

* **[Orthanc Plugins](https://github.com/orthanc-server/orthanc-plugins)**
  Collection of open-source extensions adding functionality such as DICOMweb, web viewers, database back ends, and interoperability capabilities to Orthanc deployments.

### Additional Strong Open-Source Options

* **Full PACS and DICOM archives**: Orthanc, DCM4CHEE Archive, Dicoogle, Conquest DICOM Server, and DICOMcloud.
* **Web-based medical image viewers**: OHIF Viewer, CornerstoneJS, Orthanc web viewers, and custom DICOMweb applications.
* **Desktop diagnostic and clinical viewers**: Weasis, Horos, and specialized open-source DICOM viewers.
* **DICOM development toolkits**: DCMTK, dcm4che, GDCM, PixelMed, pydicom, pynetdicom, and highdicom.
* **Medical-image processing**: ITK, SimpleITK, VTK, MITK, 3D Slicer, and ImageJ ecosystems.
* **AI-enabled imaging**: MONAI, MONAI Deploy, nnU-Net, TotalSegmentator, PyTorch, TensorFlow, and custom DICOM AI pipelines.
* **Research imaging and repositories**: XNAT, Imaging Data Commons integrations, OHDSI-linked clinical data platforms, and research DICOM archives.
* **Digital pathology**: OpenSlide, QuPath, ImageJ/Fiji, and whole-slide imaging toolkits.
* **Interoperability and APIs**: DICOMweb, HL7/FHIR servers, Orthanc REST APIs, dcm4chee REST services, and open healthcare integration engines.
* **Healthcare integration engines**: NextGen Connect (Mirth Connect), Apache Camel, HAPI FHIR, and other HL7/FHIR integration frameworks.
* **Authentication and access control**: Keycloak, OAuth/OpenID Connect, LDAP integration, and API gateway architectures.
* **Monitoring and operations**: Grafana, Prometheus, OpenSearch, ELK/OpenSearch stacks, PostgreSQL, and Kubernetes.

**Frameworks for building custom systems**: A powerful open-source PACS architecture can combine **Orthanc or DCM4CHEE** as the DICOM archive, **OHIF Viewer** for zero-footprint web viewing, **Weasis** for advanced desktop clinical visualization, **DCMTK or dcm4che** for interoperability, **pydicom and pynetdicom** for custom automation, and **MONAI** for AI-assisted imaging.

For a modern cloud-native architecture, teams can use **DICOMweb** as the primary imaging API, connect it to **Orthanc or DCM4CHEE**, use **OHIF** as the browser viewer, integrate authentication through **Keycloak**, exchange clinical context using **HL7/FHIR**, and deploy services using containers and Kubernetes. OHIF's documentation specifically supports integration with popular open-source archives such as Orthanc and DCM4CHEE through DICOMweb workflows.

## Disclaimer

* This is a **community-curated list** — not exhaustive and not an endorsement.
* PACS and medical imaging systems process sensitive healthcare information and must comply with applicable privacy, security, clinical, and data-protection regulations.
* Open-source PACS components are not automatically equivalent to a complete certified clinical or enterprise imaging environment. Production deployments require proper validation, cybersecurity, access control, audit logging, backup, disaster recovery, and interoperability testing.
